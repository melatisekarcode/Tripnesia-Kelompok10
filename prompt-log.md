# Catatan Prompt dan Evaluasi Refaktorisasi

## A. Catatan Prompt
### Prompt 1 — Halaman Cari dan Filter
Buatkan struktur HTML5 semantik berdasarkan desain Figma yang saya lampirkan. Sesuaikan dengan tampilan, teks, urutan konten, dan user flow pada desain. Gunakan elemen HTML semantik seperti header, nav, main, section, article, dan footer. Jangan gunakan CSS, inline style, Bootstrap, atau Tailwind. Buat struktur HTML yang sederhana dan mudah dibaca.
### Prompt 2 — Halaman Detail Destinasi
Buatkan struktur HTML untuk halaman Detail Destinasi berdasarkan desain Figma yang saya lampirkan. Sesuaikan dengan tampilan, teks, urutan konten, informasi destinasi, gambar, dan tombol yang terdapat pada desain. Gunakan HTML saja tanpa CSS atau inline style. Buat struktur kode yang sederhana, rapi, dan mudah dibaca.
### Prompt 3 — Halaman Simpan
Buatkan kode HTML untuk halaman Simpan berdasarkan desain yang saya lampirkan. Sesuaikan struktur dan konten dengan tampilan desain. Gunakan HTML saja tanpa CSS atau inline style. Buat kode yang sederhana, rapi, dan mudah dipahami agar dapat dijalankan melalui Visual Studio Code.
### Prompt 4 — Halaman Login, Daftar, Lupa Sandi, dan Buat Sandi
Buatkan kode HTML untuk halaman Login, Daftar, Lupa Sandi, dan Buat Sandi berdasarkan desain Figma yang saya lampirkan. Gunakan HTML saja tanpa CSS atau inline style. Sesuaikan elemen formulir, teks, tombol, dan urutan konten dengan desain. Buat struktur HTML yang sederhana dan mudah dibaca.
### Prompt 5 — Halaman Landing Page
Buatkan struktur HTML untuk halaman Landing Page berdasarkan desain Figma yang saya lampirkan. Sesuaikan struktur, teks, urutan konten, dan elemen halaman dengan desain. Gunakan HTML saja tanpa CSS atau inline style. Buat kode yang sederhana, rapi, dan mudah dibaca.

### Prompt 6 — Halaman Bantuan dan Edit Profile
Buatkan struktur HTML untuk halaman Bantuan dan Edit Profile berdasarkan desain Figma yang saya lampirkan. Sesuaikan elemen, teks, formulir, tombol, dan urutan konten dengan desain masing-masing halaman. Gunakan HTML saja tanpa CSS atau inline style. Buat kode yang sederhana, rapi, dan mudah dibaca.

## B. Evaluasi Refaktorisasi
Evaluasi refaktorisasi dilakukan untuk memeriksa dan memperbaiki kode HTML yang dihasilkan agar sesuai dengan desain Figma, memiliki struktur yang baik, serta mudah dibaca dan dipelihara.
### 1. Kesesuaian dengan Desain Figma
Memeriksa kesesuaian struktur HTML dengan desain Figma, meliputi teks, urutan konten, elemen halaman, formulir, tombol, dan informasi yang ditampilkan.
### 2. Struktur HTML
Memastikan elemen HTML tersusun dengan benar dan menggunakan elemen semantik yang sesuai, seperti header, nav, main, section, article, dan footer jika diperlukan.
### 3. Kerapian dan Keterbacaan Kode
Memeriksa indentasi, penamaan elemen, serta susunan kode agar lebih rapi, konsisten, dan mudah dipahami.
### 4. Perbaikan Struktur Kode
Memperbaiki bagian kode yang kurang sesuai, elemen yang tidak diperlukan, struktur yang kurang tepat, serta kesalahan penulisan HTML yang ditemukan selama pemeriksaan.
### 5. Pemeriksaan Hasil Refaktorisasi
Memeriksa kembali hasil perbaikan dengan membuka halaman HTML melalui browser untuk memastikan konten tampil dan struktur halaman berfungsi sesuai kebutuhan. Validasi HTML juga dilakukan menggunakan W3C Validator untuk membantu menemukan kesalahan pada kode.
---
## C. Hasil Evaluasi
Hasil evaluasi refaktorisasi digunakan untuk memastikan bahwa kode HTML setiap halaman telah diperiksa dan diperbaiki sesuai kebutuhan proyek. Pemeriksaan mencakup kesesuaian dengan desain Figma, struktur HTML, kerapian kode, serta hasil validasi.
